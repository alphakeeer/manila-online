# T14：结算记录与完整对局结果

Phase 3 · 推荐 agent：Terra。需要补充引擎观察性事件并正确过滤隐私，不能把 UI 推导当成裁决。

执行前阅读 [架构约定](../ARCHITECTURE.md) 和 [实际状态](../STATUS.md)；任务完成状态只在 STATUS 维护。

## Goal

玩家能解释每航程自己的收益变化，并看到服务器确认的终局排名。

## Scope

- 为现有 settleVoyage 增加结构明确的只读结算事件/结果，记录真实已发生的收入与扣款；沿用现有 GameEvent 接口时对新增事件收窄类型。
- 事件进入同一命令事务，与 snapshot/revision 关联；公开船只结果、私人收入明细分别投影，历史查询也做身份校验。
- UI 展示航程结果、本人收入项目、行情变化和最终总财富排名；恢复时能再次读取已提交记录。

## Non-goals

- 不改规则金额、阶段顺序或 RNG，不建设通用事件溯源。
- 不把抵押入账或保险即时支付错误归为本次航程收入，不公开对手现金/持股明细。

## Dependencies

- [T13 随时贷款与赎回的联机入口](T13-finance.md)

## Acceptance Criteria

- 同一快照和动作在增加事件前后，权威状态与 RNG 完全一致；事件追加不重复结算。
- 泊位/修理厂/货物/保险/海盗等实际收益有对应记录，跳过或未获收益不显示虚构支付。
- 结束与下一航程均有可读结果；刷新不丢最近结算，其他玩家的私人明细不在 REST/WS/历史中出现。

## Validation

- 为各种收益分支做定向规则 fixture，深比较事件增加前后的 state/RNG；检查总额和现金差异，解释非结算财务变动。
- 真实数据库提交失败/重试仅留一套结算记录；多浏览器完成航程、刷新、读取终局测试。
