# T19：单机公网部署与备份恢复手册

Phase 5 · 推荐 agent：Terra。部署配置、秘密、数据库迁移和恢复必须作为整体验证。

执行前阅读 [架构约定](../ARCHITECTURE.md) 和 [实际状态](../STATUS.md)；任务完成状态只在 STATUS 维护。

## Goal

交付可由项目所有者部署到一台公网服务器的生产包和可执行运维手册。

## Scope

- 提供多阶段容器构建、单机 Compose/等价配置、HTTPS 反向代理同源 Web/API/WSS、PostgreSQL 持久卷；数据库不对公网开放。
- 锁定已验证的 Node 运行环境和依赖，配置秘密、健康检查、迁移步骤、优雅停止及日志。
- 撰写部署/升级/回滚、Token CLI、房间关闭、备份/恢复、pepper 保管和泄漏后的撤销/轮换说明。
- 本地生产形态验收；实际公网部署需用户提供主机、域名和秘密并明确授权，不能仅凭文档声称已上线。

## Non-goals

- 不引入多实例、Kubernetes、托管云专用能力或复杂监控平台。
- 不自动购买资源或把秘密提交 Git；不承诺不兼容数据库迁移可无损自动降级。

## Dependencies

- [T18 发布前多端故障与完整对局验收](T18-release-tests.md)

## Acceptance Criteria

- 全新 Linux 环境按手册启动，健康检查正确，生产无 Vite dev server，WS 代理正常且 Cookie 仅经 HTTPS。
- 三浏览器可完成一局；重启容器保持会话与游戏，数据库不可用时拒绝写入。
- 实际完成一次备份→独立数据库恢复演练，恢复仍保留房间、游戏及 Token/会话关系；明确 pepper 必须独立安全备份。
- 升级前备份和版本兼容门禁有效；回滚步骤区分应用回退与数据库恢复，并说明可能丢失备份后的进度。

## Validation

- 在生产形态配置下运行关键 E2E、重启/健康检查、数据库端口暴露检查和备份恢复演练。
- 验证空秘密/错误 Origin/未知 stateVersion 拒绝危险运行；检查镜像与日志无秘密。
- 记录可复现命令、镜像/运行时版本及尚未执行的真实公网验证，更新 README/STATUS 发布判断。
