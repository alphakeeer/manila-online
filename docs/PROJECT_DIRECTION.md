# 产品方向

本文只维护产品目标和范围。技术决策见 [ARCHITECTURE](ARCHITECTURE.md)，执行顺序见 [ROADMAP](ROADMAP.md)，已实现事实见 [STATUS](STATUS.md)。

## 目标

实现部署在单台公网服务器上的私人多人 Manila，供本人和朋友通过各自浏览器完成一局游戏。

- 3–5 人，支持标准及现有加强海盗规则。
- 有效的 8 位 Token 才能进入房间或调用游戏接口；登录页和必要静态资源可公开访问。
- 服务器保存并裁决权威游戏状态；客户端只展示接收者视图、提交操作。
- Token 仅用于私人访问控制，不建设复杂账号系统。
- 刷新、短暂断线及服务进程重启后，可凭仍有效的原浏览器会话恢复座位与游戏。

## MVP 交付范围

- Token 输入、验证、会话，以及管理员生成/撤销 Token。
- 房间创建、房间码加入、昵称、准备、房主开始、未开局离开。
- 完整竞拍、购股、下水、放置、移动、领航员、海盗、财务、结算与终局。
- 隔离各玩家资金与股份；公共版图、公共动作和最终排名可见。
- 实时同步、重复命令去重、并发冲突反馈、断线恢复。
- 数据库保存房间、成员、会话、游戏快照及命令结果；事务成功后通知客户端。
- 桌面和手机基本可用；明确展示等待、断线、拒绝和结算结果。
- 单机部署说明、数据库备份/恢复、健康检查及最小管理 CLI。

## 非目标

- 注册、密码找回、OAuth、个人资料、复杂账号/权限体系。
- 公开大厅、匹配、排行榜、聊天、观战、AI 玩家、语音或视频。
- 客户端权威或离线游戏作为正式产品模式；旧热座入口仅为迁移期间的本地验证。
- 跨设备或清除 Cookie 后自动找回原座位；多人共享门禁 Token 不等于共享玩家身份。
- 自动代打、掉线托管、对局中换人、任意改分和玩家撤销动作。
- 多服务实例、Redis、微服务、Kubernetes、完整事件溯源和通用游戏框架。

## 发布判断

以 ROADMAP 的 Phase 门槛和任务验收为依据，不按代码行数或主观百分比判断完成。
所有联网阶段都应交付可在浏览器观察的结果；公网使用以最终发布验收通过为前提。
