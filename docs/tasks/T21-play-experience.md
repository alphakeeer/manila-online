# T21：游玩体验与动效重构

Phase 4 补充 · 推荐 agent：Luna。纯前端展示层任务，不修改规则引擎、协议或服务端。

执行前阅读 [架构约定](../ARCHITECTURE.md) 和 [实际状态](../STATUS.md)；任务完成状态只在 STATUS 维护。

## Goal

把“规则搬上网页”的界面重构为好玩、顺滑、有参与感的对局体验，同时支持手机和电脑。

## Scope

- 版图：同一舢板元素在航道与泊位间平滑移动；下水与领航员选择在版图实时预览；可推进的舢板高亮并可直接点击；同伙标记显示玩家昵称首字。
- 决策面板：竞拍步进器与快捷出价、商品卡片式购股/选货、按航道安排下水与预设、按区域分组的放置列表与提示、带骰面和落点的推进按钮、带结果描述的领航选项。
- 参与感：根据接收者快照差异生成航海日志与手机吐司、掷骰动画、轮到你横幅、标题提示、振动与可静音合成音效、在线状态、航程结算卡、终局排名与彩带。
- 布局：桌面三栏（日志 / 版图 / 操作），平板两栏，手机为版图 + 可收起底部操作面板；保留 reduced motion。
- 修正版图展示映射：港口泊位字母与图面一致（A 在下），修船厂同伙标记位于右侧码头。

## Non-goals

- 不修改规则、协议字段、命令语义或服务端投影；日志只由公开/本人快照推导，不推断私有数据。
- 不引入新的运行时依赖或外部字体/CDN。

## Dependencies

- [T16 可用性与移动端](T16-usability.md)、[T17 资源预算](T17-assets.md)

## Acceptance Criteria

- 既有三条 Chromium E2E（会话、三人竞拍、三人完整对局）在新界面下通过，选择器语义保持。
- 新增单元测试覆盖快照差异日志、泊位标注方向和手机底部面板样式约束。
- 桌面 1440×900、平板 1180×820、手机 iPhone 13 视口完成整局截图检查，无阻挡操作的覆盖层。

## Validation

- `npm test`、`npm run build`、`E2E_FULL_GAME=1 npm run test:e2e`（需与 CI 相同的放宽限流环境变量）。
- 三视口自动对局截图人工复核。
