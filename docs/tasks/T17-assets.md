# T17：按需加载与图片体积预算

Phase 4 · 推荐 agent：Luna。资源引用、衍生图片与构建测量可独立完成，不涉及规则或身份。

执行前阅读 [架构约定](../ARCHITECTURE.md) 和 [实际状态](../STATUS.md)；任务完成状态只在 STATUS 维护。

## Goal

减少公网首次进入版图的图片传输，保持现有标注几何关系和原始素材。

## Scope

- 先测量实际冷加载网络请求，再将动态原图查找改为显式资源表和适当尺寸的衍生 WebP/AVIF 等浏览器资源。
- 保留 manila_assets 原图与坐标 JSON，衍生物单独存放并提供可复现生成步骤。
- 记录 production build 与浏览器加载预算，新增轻量检查防止再次引用全部巨型原图。

## Non-goals

- 不删除原图、不改标注坐标系统、不引入 CDN 或资源服务。
- 不把 dist 总体积直接等同于实际网络传输，不改变棋盘内容。

## Dependencies

- [T01 迁移现有代码并锁定验证入口](T01-workspace.md)

## Acceptance Criteria

- 与迁移后基线比较，冷加载游戏页面的图片实际传输至少减少 60%，目标不超过 5 MB；若达不到须记录逐图瓶颈并继续优化，不以删内容达标。
- 版图各热点与船只/同伙标记仍对齐，桌面和手机主要文字清晰。
- 生产运行不需要 annotator 服务或文件目录扫描，资源 404 为零。

## Validation

- 运行 build，记录每张主要图片产物大小与无缓存浏览器 Network 测量；提交前后对比报告至 STATUS。
- 现有坐标/UI 测试通过，两种屏宽截图对比；检查原图未修改，生成步骤可重跑。
